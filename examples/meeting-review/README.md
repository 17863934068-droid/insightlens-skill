# 合成示例：团队会议纪要

这是人为编写的流程验证材料，不来自真实访谈，也不代表真实用户需求。

## 文件

- `input.json`：研究问题、四份节选、三位不同受访者和 12 条待审阅结论。M04 是 U11 的追访，M05 故意未提供。
- `sample-review.json`：先前试运行、规则修订后的审阅记录。它作为输出示例随包提供，不能用来证明新一轮独立测试的效果。

## 试用步骤

1. 让 AI 加载核心 Skill，读取 `input.json`，审阅其中全部结论；暂时不要给它读取示例输出。
2. 查看是否保留结论原文、给出可定位的原文依据，并区分语义疑点和材料缺失。
3. 再对照 `sample-review.json`。措辞不必一致，重点检查证据是否支持判断。若有分歧，先回原文，不以示例输出强制裁决。

可复制指令：

```text
使用 $insightlens-interview-analysis，读取 examples/meeting-review/input.json。
只审阅全部 claims，不先改写原结论；仅使用提供的 sources。
输出 JSON，覆盖每条输入；有疑点时指出具体片段、原因及相关证据。
缺少材料时单独记录范围提示，不把它当成已证实错误。
不要读取 sample-review.json；不要替我确认任何结论。
```

## 三个值得核对的例子

| 结论 | 原文关系 | 需要区分 |
| --- | --- | --- |
| R09 | “周五前必须交”逐字出现，但描述的是系统误写 | 引文存在不等于结论成立 |
| R11 | 指定原文是“我不反对系统给草稿”，引用遗漏了“不” | 指定引用失配与整项分析的关系 |
| R12 | 所指 M05 没有提供 | 无法核验不等于已确认错误 |

示例审阅记录包含 7 项疑点，涉及 6 条结论；5 条在所提供材料内未发现疑点；1 条仅有材料缺失提示。数量用于理解这份记录，不是模型应凑齐的目标。
